⚙️ Workflows trong ERPNext - Phân tích Chi tiết

1. Workflows là gì?

📋 Định nghĩa

Workflows là một tính năng của Frappe Framework (không phải ERPNext), cho phép bạn tạo các quy trình duyệt (approval workflows) tự động cho bất kỳ DocType nào.

Thay vì submit document trực tiếp, bạn có thể định nghĩa một chuỗi các States (trạng thái) mà document phải đi qua, với các Actions (hành động) và Transitions (chuyển đổi) được kiểm soát bởi Roles (vai trò) và Conditions (điều kiện).

🎯 Mục đích

  • Tạo approval workflows (duyệt đơn hàng, phê duyệt chi phí)
  • Multi-level approval (duyệt nhiều cấp)
  • Conditional routing (điều hướng theo điều kiện)
  • Permission control (kiểm soát quyền theo state)
  • Auto-update fields (tự động cập nhật trường)
  • Email notifications (thông báo qua email)

🔧 Thành phần chính

  • Workflow: Document chứa toàn bộ cấu hình
  • Workflow States: Các trạng thái (Draft, Pending, Approved...)
  • Workflow Transitions: Quy tắc chuyển đổi giữa states
  • Workflow Actions: Buttons (Approve, Reject, Submit...)
  • Roles: Vai trò được phép thực hiện actions
  • Conditions: Điều kiện Python để kiểm tra

✅ Ưu điểm

  • Không cần code, cấu hình qua UI
  • Áp dụng cho bất kỳ DocType nào
  • Linh hoạt với conditions và roles
  • Audit trail đầy đủ
  • Tích hợp email notifications
  • Có thể customize qua scripts

2. Kiến trúc Workflow

Component DocType Mô tả
Workflow Workflow Document chính chứa tên, DocType áp dụng, state field, active status
Workflow States Workflow Document State Child table: Danh sách các states (Draft, Pending, Approved...)
Workflow Transitions Workflow Document Transition Child table: Quy tắc chuyển đổi từ state A → state B
Workflow Action Workflow Action Master Master data: Các actions có thể dùng (Approve, Reject, etc.)

Workflow Document Structure:

Workflow { workflow_name: "SO Test Workflow" document_type: "Sales Order" workflow_state_field: "workflow_state" // Field trên SO để lưu state is_active: 1 send_email_alert: 0 // Child table: States states: [ { state: "Pending" allow_edit: "All" // Ai cũng edit được doc_status: 0 // Draft }, { state: "Approved" allow_edit: "Test Approver" // Chỉ Approver edit được doc_status: 1 // Auto-submit khi vào state này update_field: "status" // Tự động update field này update_value: "Approved" // với value này } ] // Child table: Transitions transitions: [ { state: "Pending" // Từ state action: "Approve" // Action button next_state: "Approved" // Đến state allowed: "Test Junior Approver" // Role được phép allow_self_approval: 1 condition: "doc.grand_total < 200" // Điều kiện Python }, { state: "Pending" action: "Approve" next_state: "Approved" allowed: "Test Approver" // Role khác allow_self_approval: 1 condition: "doc.grand_total >= 200" } ] }

💡 Key Points:

  • Conditional Routing: Dựa vào grand_total, hệ thống tự động route đến Junior hoặc Senior Approver
  • Auto-Submit: Khi vào state "Approved" với doc_status=1, document tự động được submit
  • Permission Control: Ở state "Approved", chỉ "Test Approver" có thể edit
  • Field Update: Tự động set field "status" = "Approved" khi vào state này

4. Code Example: Tạo Workflow bằng Python

import frappe def make_sales_order_workflow(): # 1. Tạo roles cần thiết frappe.get_doc( doctype="Role", role_name="Test Junior Approver" ).insert(ignore_if_duplicate=True) frappe.get_doc( doctype="Role", role_name="Test Approver" ).insert(ignore_if_duplicate=True) # 2. Tạo Workflow document workflow = frappe.get_doc({ "doctype": "Workflow", "workflow_name": "SO Test Workflow", "document_type": "Sales Order", "workflow_state_field": "workflow_state", "is_active": 1, "send_email_alert": 0, }) # 3. Thêm States workflow.append("states", { "state": "Pending", "allow_edit": "All", "doc_status": 0 }) workflow.append("states", { "state": "Approved", "allow_edit": "Test Approver", "doc_status": 1, # Auto-submit "update_field": "status", "update_value": "Approved" }) workflow.append("states", { "state": "Rejected", "allow_edit": "None", "doc_status": 2 # Cancelled }) # 4. Thêm Transitions - Duyệt đơn nhỏ (< 200) workflow.append("transitions", { "state": "Pending", "action": "Approve", "next_state": "Approved", "allowed": "Test Junior Approver", "allow_self_approval": 1, "condition": "doc.grand_total < 200" }) # 5. Transition - Duyệt đơn lớn (>= 200) workflow.append("transitions", { "state": "Pending", "action": "Approve", "next_state": "Approved", "allowed": "Test Approver", "allow_self_approval": 1, "condition": "doc.grand_total >= 200" }) # 6. Transition - Từ chối workflow.append("transitions", { "state": "Pending", "action": "Reject", "next_state": "Rejected", "allowed": "Test Approver", "allow_self_approval": 1 }) workflow.insert(ignore_permissions=True) return workflow # Sử dụng workflow from frappe.model.workflow import apply_workflow so = frappe.get_doc("Sales Order", "SAL-ORD-2024-00001") apply_workflow(so, "Approve") # Trigger action "Approve"

5. Use Cases trong ERPNext

1. Sales Order Approval

Duyệt đơn hàng trước khi giao hàng. Conditional routing dựa vào giá trị đơn hàng.

States:
Draft → Pending → Approved

Conditions:

  • grand_total < 200: Junior Approver
  • grand_total >= 200: Senior Approver

2. Expense Claim Approval

Duyệt chi phí của nhân viên. Auto-update field "approval_status".

States:
Draft → Pending → Approved Rejected

Auto-update:

  • update_field: "approval_status"
  • update_value: "Approved" / "Rejected"

3. Leave Application Workflow

Duyệt đơn xin nghỉ của nhân viên. Tự động update field "status".

States:
Open → Approved Rejected

Features:

  • Email notification cho manager
  • Auto-update leave balance
  • Multi-level approval nếu > X days

4. Purchase Order Approval

Duyệt đơn đặt hàng trước khi gửi cho supplier. Phân cấp theo giá trị.

States:
Draft → Pending → Approved

Levels:

  • < 10M: Manager approval
  • 10M - 50M: Director approval
  • > 50M: CEO approval

5. Journal Entry Workflow

Duyệt bút toán kế toán. KHÔNG auto-submit nếu có workflow.

States:
Draft → Pending Review → Approved

Important:

  • Auto-submit DISABLED khi có workflow
  • Phải duyệt qua workflow trước
  • Check: je.meta.get_workflow()

6. Custom Material Request

Duyệt yêu cầu vật tư. Multi-step approval với budget check.

States:
Draft → Pending → Budget Check → Approved

Conditions:

  • Check budget availability
  • Check stock levels
  • Verify cost center authorization

6. Workflow API (Frappe Framework)

Function Mô tả Example
get_workflow_name(doctype) Lấy tên workflow active cho một DocType workflow = get_workflow_name("Sales Order")
apply_workflow(doc, action) Trigger một action trên document apply_workflow(sales_order, "Approve")
is_transition_condition_satisfied(transition, doc) Kiểm tra điều kiện của transition if is_transition_condition_satisfied(t, doc): ...
doc.meta.get_workflow() Kiểm tra xem document có workflow không if not je.meta.get_workflow(): je.submit()
get_transitions(doc) Lấy danh sách transitions available cho user transitions = get_transitions(sales_order)

Permission Check Flow:

def validate_workflow_conditions(doc): # 1. Lấy workflow cho doctype này workflow = get_workflow_name(doc.doctype) if not workflow: return # Không có workflow, skip # 2. Load workflow document workflow_doc = frappe.get_doc("Workflow", workflow) current_state = doc.get(workflow_doc.workflow_state_field) # 3. Lấy roles của user hiện tại user_roles = frappe.get_roles() # 4. Tìm transitions hợp lệ valid_transitions = [] for transition in workflow_doc.transitions: if transition.next_state == current_state: # Kiểm tra role if transition.allowed not in user_roles: continue # Kiểm tra condition if not is_transition_condition_satisfied(transition, doc): continue valid_transitions.append(transition) # 5. Nếu không có transitions hợp lệ → reject if not valid_transitions: frappe.throw( _("You are not allowed to update as per workflow conditions."), title=_("Insufficient Permissions") )

7. Khả năng Tuỳ biến (Customization)

✨ Workflows CÓ THỂ tuỳ biến toàn bộ quy trình:

  • ✅ Áp dụng cho BẤT KỲ DocType nào (Sales Order, Purchase Order, Journal Entry, custom DocTypes...)
  • ✅ Tạo custom states theo nhu cầu nghiệp vụ
  • ✅ Định nghĩa custom actions/buttons (Approve, Reject, Send Back, Escalate...)
  • ✅ Viết Python conditions phức tạp để routing
  • ✅ Phân quyền chi tiết theo roles và states
  • ✅ Tự động cập nhật custom fields khi chuyển state
  • ✅ Gửi email notifications tự động
  • ✅ Tích hợp với client scripts và server scripts

Ví dụ Custom Conditions:

# Điều kiện đơn giản condition: "doc.grand_total < 200" # Điều kiện phức tạp hơn condition: "doc.grand_total >= 1000 and doc.customer_group == 'Corporate'" # Kiểm tra user condition: "doc.owner == frappe.session.user" # Kiểm tra ngày condition: "getdate(doc.posting_date) >= getdate(today())" # Kiểm tra child table condition: "len(doc.items) > 5" # Kiểm tra custom field condition: "doc.custom_priority == 'High' and doc.custom_department == 'IT'" # Complex logic với custom method condition: "frappe.call('my_app.api.check_budget', doc=doc.name)"

Integration với Scripts:

// Client Script (JavaScript) - Thêm validation khi workflow action frappe.ui.form.on('Sales Order', { before_workflow_action: function(frm) { if (frm.selected_workflow_action === 'Approve') { // Custom validation trước khi approve if (frm.doc.grand_total > 1000000) { frappe.msgprint('Please add justification for large orders'); return false; // Prevent action } } }, after_workflow_action: function(frm) { // Custom logic sau khi workflow action thành công if (frm.doc.workflow_state === 'Approved') { frappe.show_alert({ message: 'Order approved! Creating delivery note...', indicator: 'green' }); } } });

8. Lưu ý Quan trọng

✅ Best Practices

  • Đặt tên states rõ ràng, dễ hiểu
  • Sử dụng conditions để routing tự động
  • Test kỹ các transitions với nhiều roles
  • Document workflow logic cho team
  • Sử dụng email alerts để thông báo
  • Backup trước khi modify workflow

⚠️ Cảnh báo

  • Workflow KHÔNG thể cascade delete
  • Thay đổi workflow ảnh hưởng documents hiện có
  • Cẩn thận với auto-submit (doc_status=1)
  • Test conditions kỹ, tránh deadlock
  • Không nên quá nhiều states (max 5-7)
  • Workflow có thể làm chậm UI nếu phức tạp

❌ Limitations

  • Không hỗ trợ parallel approvals (cùng lúc)
  • Conditions phải là Python expression đơn giản
  • Không thể conditional actions (phải tạo nhiều transitions)
  • Email template limitations
  • Không có built-in escalation (timeout)
  • UI có thể confusing với nhiều actions

🎯 Kết luận:

Workflows trong ERPNext là một công cụ cực kỳ mạnh mẽ cho phép bạn tuỳ biến toàn bộ quy trình duyệt và kiểm soát documents mà KHÔNG CẦN VIẾT CODE.

Bạn có thể áp dụng workflow cho bất kỳ module nào: Selling, Buying, HR, Accounting, Stock, Projects... và thậm chí custom modules của riêng bạn.

Với khả năng conditional routing, role-based permissions, và auto field updates, Workflows là giải pháp hoàn hảo cho các tổ chức cần quy trình duyệt nghiêm ngặt và có audit trail đầy đủ.
